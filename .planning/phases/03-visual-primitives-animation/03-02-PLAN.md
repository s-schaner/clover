Create `components/ui/FadeInOnScroll.tsx` as a `'use client'` component.

**Props interface:**
```typescript
interface FadeInOnScrollProps {
  children: React.ReactNode;
  className?: string;
  delay?: number;      // seconds, default 0
  y?: number;          // travel distance in px, default 40 (within 32-48px dramatic range from CONTEXT.md)
  as?: React.ElementType; // render as different element (div, section, etc.), default 'div'
}
```

**Implementation details:**

1. Import `motion` and `useReducedMotion` from `framer-motion`.

2. Call `useReducedMotion()` at the top of the component. The hook returns `boolean | null` (null on SSR). Treat both `true` as "skip animation". When `shouldReduceMotion` is truthy:
   - Return a plain element (using `as` prop or default `div`) with `className` applied
   - Children render at full opacity with no transform — NO animation, NO opacity:0 flash
   - This is the critical accessibility requirement from CONTEXT.md: "All scroll animations completely absent when prefers-reduced-motion: reduce is set"

3. When animation is active, use framer-motion's `motion.div` (or `motion[as]` equivalent — use `motion.create(as)` if the `as` prop is provided and is not 'div'):
   - `initial={{ opacity: 0, y }}` — start invisible, translated down by `y` px
   - `whileInView={{ opacity: 1, y: 0 }}` — animate to visible, at rest position
   - `viewport={{ once: false, amount: 0.2 }}`:
     - `once: false` — animation replays every time element re-enters viewport (CONTEXT.md requirement)
     - `amount: 0.2` — triggers when 20% of element is visible
   - `transition={{ duration: 0.6, ease: [0.21, 0.47, 0.32, 0.98], delay }}`:
     - Duration matches `--duration-slow` (600ms)
     - Ease matches `--ease-premium` cubic-bezier
     - Optional delay for manual sequencing

4. Only animate `opacity` and `y` (transform: translateY) — these are GPU-composited properties. Never animate width, height, top, left, or background-color.

**What NOT to do:**
- Do NOT use `viewport={{ once: true }}` — animations must replay on re-entry
- Do NOT use the CSS-only `.fade-in-scroll` class from globals.css — this component replaces that approach with framer-motion for orchestration capability
- Do NOT forget the `useReducedMotion` guard — content must be visible for reduced-motion users
- Do NOT use `useInView` hook separately — `whileInView` prop handles everything
- Do NOT use `AnimatePresence` — not needed for scroll-triggered animations

**Note on the `as` prop:** For simplicity, if `as` is needed as something other than `div`, use a generic approach. The simplest implementation is to always render `motion.div` and let the consumer wrap in the appropriate semantic element. Document in a comment that the `as` prop is for future flexibility but `motion.div` is the default and recommended usage.

Create `components/ui/StaggerChildren.tsx` as a `'use client'` component. This file exports two components: `StaggerChildren` (wrapper) and `StaggerItem` (individual animated item).

**Critical API note from research:** `staggerChildren` is DEPRECATED in framer-motion 12 (motion-dom). The `stagger()` function only supports 1D ordering (`"first"`, `"last"`, `"center"`, flat index). For the diagonal top-left cascade required by CONTEXT.md, delay must be computed manually as `(row + col) * interval` per item.

**StaggerItem props interface:**
```typescript
interface StaggerItemProps {
  children: React.ReactNode;
  index: number;          // flat index in the grid (0-based)
  columns: number;        // number of columns in the grid
  className?: string;
  staggerInterval?: number; // seconds per diagonal step, default 0.08
}
```

**StaggerItem implementation:**

1. Import `motion` and `useReducedMotion` from `framer-motion`.

2. Compute `row` and `col` from `index` and `columns`:
   ```typescript
   const row = Math.floor(index / columns);
   const col = index % columns;
   ```

3. Compute diagonal delay: `const delay = (row + col) * staggerInterval;`

4. Guard with `useReducedMotion()` — when truthy, return a plain `<div>` with className and children (no animation, full visibility).

5. When animation is active, use `motion.div` with:
   - `initial={{ opacity: 0, y: 40 }}` — start invisible, translated down 40px
   - `whileInView={{ opacity: 1, y: 0 }}` — animate to visible
   - `viewport={{ once: false, amount: 0.1 }}`:
     - `once: false` for replay on re-entry
     - `amount: 0.1` (10% visible) — lower threshold than FadeInOnScroll because individual cards are smaller elements; prevents flickering at viewport edge (Pitfall 2 from research)
   - `transition={{ duration: 0.6, ease: [0.21, 0.47, 0.32, 0.98], delay }}`

6. Each StaggerItem manages its own viewport tracking independently via `whileInView`. There is NO parent-child stagger propagation — this is the correct approach for diagonal cascades in framer-motion 12.

**StaggerChildren props interface:**
```typescript
interface StaggerChildrenProps {
  children: React.ReactNode;
  className?: string;
}
```

**StaggerChildren implementation:**

This is a simple wrapper that provides the grid layout container. It does NOT use framer-motion at all — it's a plain div with the grid className. The animation is entirely in `StaggerItem`.

```typescript
export function StaggerChildren({ children, className }: StaggerChildrenProps) {
  return <div className={className}>{children}</div>;
}
```

The purpose of exporting `StaggerChildren` is semantic clarity and future flexibility (if we later need to add a parent-level viewport observer, we have the wrapper in place).

**Usage pattern (document in a comment at the top of the file):**
```tsx
<StaggerChildren className="grid grid-cols-3 gap-6">
  {items.map((item, i) => (
    <StaggerItem key={item.id} index={i} columns={3}>
      <Card {...item} />
    </StaggerItem>
  ))}
</StaggerChildren>
```

**What NOT to do:**
- Do NOT use `staggerChildren` in transition — it's deprecated in framer-motion 12
- Do NOT use `stagger()` from framer-motion for diagonal cascade — it only supports 1D ordering
- Do NOT put a `motion.div` parent with `variants` and `staggerChildren` orchestration — each item self-manages
- Do NOT use `viewport={{ once: true }}` — must replay on re-entry
- Do NOT nest `motion.div` inside `motion.div` unnecessarily
