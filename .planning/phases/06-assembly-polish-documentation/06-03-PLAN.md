Create `docs/DESIGN_SYSTEM.md`. Read `app/globals.css` and `app/layout.tsx` to extract the exact token values. The document must be accurate to the actual codebase, not copied from planning docs.

Structure the document with these sections:

1. **Design Philosophy** — Pure B&W, no accent colors, no border-radius, geometric fractal patterns as sole visual texture, sharp engineering aesthetic. Explain the dark/light section alternation rhythm (dark-light-dark-light-dark).

2. **Color Tokens** — List every color in the `@theme` block with its hex value and semantic purpose. Group into Dark Surface and Light Surface. Include the pure anchors (black, white). Note: raw hex values must NEVER appear in component code — always use the semantic token.

3. **Typography** — Three font families:
   - Space Grotesk (--font-display): headings, brand text, hero
   - Inter (--font-body): body text, paragraphs, labels
   - JetBrains Mono (--font-mono): code accents, tech tags
   Document the Tailwind utility classes: `font-display`, `font-body`, `font-mono`. Note that fonts are loaded via `next/font/google` in layout.tsx with `display: 'swap'`.

4. **Spacing Tokens** — All `:root` custom properties with their clamp() values and what each controls:
   - --nav-height, --section-padding-y, --section-padding-x, --card-padding, --gap-grid, --text-hero, --text-section
   Explain that clamp() values are in `:root` (not `@theme`) because Tailwind v4 cannot statically analyze clamp().

5. **Animation Tokens** — Duration and easing values from `@theme`:
   - --duration-fast, --duration-base, --duration-slow
   - --ease-out, --ease-in-out, --ease-premium
   Note the reduced-motion policy: all animations respect `prefers-reduced-motion: reduce`.

6. **Pattern Tokens** — --pattern-opacity-dark (0.06), --pattern-opacity-light (0.04), --pattern-size (40px). Explain the fractal grid texture system.

7. **What Never Goes In** — Explicit constraints: no border-radius anywhere, no accent/brand colors, no drop shadows (except subtle card lift on hover), no gradients on surfaces.

  <action>
Create `docs/COMPONENTS.md`. Read ALL component files in components/ and the data files in lib/ to document the actual API of each component. Do NOT guess props — read the TypeScript interfaces from the source files.

Structure the document with these sections:

1. **Architecture Overview** — Component topology tree (Server vs Client components), the page composition pattern (app/page.tsx is a thin fragment importing 5 sections), layout.tsx role (html, body, fonts, Navigation).

2. **Layout Components**
   - **Navigation** (`components/layout/Navigation.tsx`): Client component. Scroll-spy, mobile hamburger overlay, focus trap. No props — reads from lib/constants.ts. Desktop links at md+ breakpoint, hamburger below md.
   - **SectionWrapper** (`components/ui/SectionWrapper.tsx`): Server component. Props: `id` (string), `theme` ('dark' | 'light'), `className?` (string), `children`. Provides anchor ID, scroll-margin-top, section padding, theme class.

3. **UI Primitives**
   - **FadeInOnScroll**: Props from the actual component. Explain: wraps children, fades in with Y-translate when entering viewport. Respects reduced-motion.
   - **StaggerChildren + StaggerItem**: StaggerChildren is a plain div (no framer-motion). StaggerItem props: `index`, `columns`, `children`, `className?`. Each item self-manages viewport tracking with diagonal cascade delay.
   - **HoverLift**: Props from actual component. Wraps children with scale-up on hover.
   - **GridPattern**: Props: `theme` ('dark' | 'light'). Absolute-positioned SVG fractal grid texture. Parent must have `position: relative`.
   - **GeometryAccent**: No props. Four-leaf clover SVG draw animation for hero. Absolute-positioned. Parent must have `position: relative`.

4. **Section Components** — For each of the 5 sections:
   - Component name and file path
   - Server or Client component
   - Theme (dark/light)
   - What it contains (heading, cards, grid layout)
   - Data source (which constants from lib/constants.ts)
   - Grid responsive behavior (cols at each breakpoint)

5. **Card Components** — For each card:
   - Props (from actual TypeScript interface)
   - What it renders
   - Built-in behaviors (e.g., "HoverLift is built into ServiceCard — do NOT wrap in HoverLift again")

6. **Data Layer**
   - `lib/types.ts`: List all exported interfaces/types with their fields
   - `lib/constants.ts`: List all exported constants, their types, and what section consumes them

7. **Adding New Content** — Step-by-step instructions for three common operations:
   - How to add a new portfolio item (add to PORTFOLIO_ITEMS in constants.ts, matching PortfolioItem type)
   - How to add a new team member (add to TEAM_MEMBERS, matching TeamMember type)
   - How to add a new service (add to SERVICES, matching ServiceItem type, add icon to ICON_MAP in ServiceCard.tsx)
