**Component structure (locked decisions from CONTEXT.md):**

1. **Card layout:** Large avatar emphasis — avatar area takes ~60% of card height, name/role/social below.

2. **MonogramAvatar sub-component** (internal, not exported):
   - SVG element with `viewBox="0 0 120 120"`, `fill="none"`, `stroke="currentColor"`, `className="w-full h-full"`
   - `aria-hidden="true"` (decorative)
   - **Outer frame:** Rect at `x="4" y="4" width="112" height="112"` with `strokeWidth="0.5" opacity="0.3"` — subtle engineering blueprint container
   - **Monogram text:** SVG `<text>` element centered in viewBox:
     - `x="55" y="62"` (slightly left of center to account for two-char width, slightly below center for optical centering)
     - `dominantBaseline="middle" textAnchor="middle"` for reliable centering
     - `fontFamily="var(--font-display)"` for Space Grotesk — if it doesn't resolve in SVG, fall back to `fontFamily="'Space Grotesk', sans-serif"` as a string literal
     - `fontSize="36" fontWeight="700"` for bold, large presence
     - `stroke="none" fill="currentColor"` (text is filled, not stroked)
     - `letterSpacing="-1"` for tight tracking
     - Renders `member.initials` (MW, MD, PK, SS)
   - **CloverAccentMini sub-component** (internal):
     - Simplified four-petal clover from GeometryAccent's bezier pattern — outer petals only, no veins, no frame, no crosshairs
     - Props: `cx: number, cy: number, size?: number` (default size 10)
     - Each petal is a cubic bezier from center, bulging out, curving back — same control-point pattern as GeometryAccent's `generateCloverPath()`
     - `fill="none" stroke="currentColor" strokeWidth="0.8"`
     - Position at approximately `cx={88} cy={28}` relative to the 120x120 viewBox — top-right of the letter cluster
     - The bezier path (from research):
       ```
       half = size / 2
       d = M cx cy
           C cx+h*.6 cy-h*.75, cx+size cy-h*.4, cx+size cy     // right petal
           C cx+size cy+h*.4, cx+h*.6 cy+h*.75, cx cy
           C cx-h*.75 cy-h*.6, cx-h*.4 cy-size, cx cy-size      // top petal
           C cx+h*.4 cy-size, cx+h*.75 cy-h*.6, cx cy
           C cx-h*.6 cy-h*.75, cx-size cy-h*.4, cx-size cy      // left petal
           C cx-size cy+h*.4, cx-h*.6 cy+h*.75, cx cy
           C cx+h*.75 cy+h*.6, cx+h*.4 cy+size, cx cy+size      // bottom petal
           C cx-h*.4 cy+size, cx-h*.75 cy+h*.6, cx cy
       ```

Create `components/cards/ContactForm.tsx` as a `'use client'` component.

**This is NOT a card wrapped in HoverLift** — it's a form component. No HoverLift wrapper.

**Form structure:**
- `<form>` element with:
  - `onSubmit={(e) => e.preventDefault()}` — no-op, purely visual
  - `aria-label="Contact form - not yet active"` (accessibility context)
  - `noValidate` (no browser validation on a non-functional form)
  - Classes: `flex flex-col gap-6 max-w-lg`

**Fields (3 total):**

Each field follows the same pattern — label + input wrapped in a flex-col div:

1. **Name field:**
   - Label: `<label htmlFor="contact-name">Name</label>`
   - Label classes: `font-body text-sm text-on-surface-muted uppercase tracking-wider`
   - Input: `<input id="contact-name" type="text" name="name" autoComplete="name" readOnly />`
   - Input classes: `bg-transparent border border-on-surface-subtle/30 px-4 py-3 font-body text-on-surface placeholder:text-on-surface-subtle/40 focus:outline-none focus:border-on-surface/60 transition-colors`
   - Placeholder: `"Your name"`

2. **Email field:**
   - Label: `<label htmlFor="contact-email">Email</label>`
   - Input: `<input id="contact-email" type="email" name="email" autoComplete="email" readOnly />`
   - Same classes as name. Placeholder: `"your@email.com"`

3. **Message field:**
   - Label: `<label htmlFor="contact-message">Message</label>`
   - Textarea: `<textarea id="contact-message" name="message" rows={5} readOnly />`
   - Same classes as inputs plus `resize-none`
   - Placeholder: `"Tell us about your project"`

**Submit button:**
- `<button type="submit" disabled aria-disabled="true" aria-describedby="contact-coming-soon">`
- Text content: `Coming Soon`
- Classes: `font-display text-sm tracking-widest uppercase px-8 py-4 border border-on-surface/20 text-on-surface/30 cursor-not-allowed opacity-50`
- No border-radius

**Screen reader context:**
- `<p id="contact-coming-soon" className="sr-only">Form submission is not yet active. Please use the email link above.</p>`

**Design constraints:**
- Contact section is DARK theme — use dark tokens: `text-on-surface`, `text-on-surface-muted`, `border-on-surface-subtle/30`
- Do NOT use light-section tokens (no `on-surface-light-*`)
- All inputs are `readOnly` (not `disabled`) — they remain focusable, feel like a preview
- Only the submit button is `disabled` — communicates "not connected yet"
- No form state, no useState, no validation logic — purely visual
- No border-radius on inputs or button
- `transition-colors` on inputs for smooth focus border change (not `duration-[--duration-fast]` — that token may not exist as a Tailwind utility; use plain `transition-colors` which defaults to 150ms)

Export as named export: `export function ContactForm(...)`.
